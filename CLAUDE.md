# CLAUDE.md

## Project Overview

Personal portfolio, blog, and games hub at **korikosmos.dev**, with three switchable skins: Mandy mode (the default), the modern skin, and a Web 1.0 "retro" skin. Built with Astro 5 (SSR mode) using the Node standalone adapter, with React islands (`@astrojs/react`) for components and interactivity, styled with Tailwind CSS 3 + DaisyUI 4.

## Tech Stack

- **Framework:** Astro 5 (`output: 'server'`, `@astrojs/node` standalone adapter) for routing, SSR data fetching, content collections, and API routes
- **UI:** React 19 via `@astrojs/react` — all component and page-body markup is `.tsx`; Astro `.astro` pages are thin wrappers that fetch data server-side and render a React component with the result as props
- **Styling:** Tailwind CSS 3.3 + DaisyUI 4.12 (5 custom themes: `dark`, `light`, `forest`, `spider-man`, `batman` for the modern skin; `src/styles/retro.css` for the retro skin; `src/styles/mandy.css` plus 4 `mandy-*` DaisyUI themes for Mandy mode)
- **TypeScript:** Strict mode (`astro/tsconfigs/strict`)
- **Deployment:** Docker (multi-stage build, Node 22 Alpine, port 4321)
- **CMS:** Keystatic (admin at `/keystatic`; schemas in `keystatic.config.ts`). GitHub mode everywhere: edits authenticate via a GitHub App and land as commits (`KEYSTATIC_GITHUB_CLIENT_ID`/`KEYSTATIC_GITHUB_CLIENT_SECRET`/`KEYSTATIC_SECRET` + `PUBLIC_KEYSTATIC_GITHUB_APP_SLUG`). In production the admin routes are only built when the client id is present at build time (guard in `astro.config.mjs`; Dockerfile passes it as a build arg). `keystatic.config.ts` is imported by the browser — only `import.meta.env`, never `process.env`. `/admin` 301-redirects to `/keystatic`. `src/middleware.ts` forces the request origin on `/api/keystatic/github/*` routes to the canonical `site` (only in `import.meta.env.PROD`): behind the container's reverse proxy the Node server sees the internal host (`localhost:4321`), so Keystatic would otherwise build `redirect_uri=https://localhost/...` and GitHub rejects the OAuth sign-in. The GitHub App must have both `https://korikosmos.dev/api/keystatic/github/oauth/callback` (prod) and `http://127.0.0.1:4321/api/keystatic/github/oauth/callback` (dev) registered as callback URLs.

## Commands

- `npm run dev` — start dev server at `localhost:4321`
- `npm run build` — production build (outputs to `dist/`)
- `npm run check` — type-check TypeScript and checked JS (`tsc --noEmit`). Does not type-check `.astro` templates, so also run `build` and `test:render`
- `npm test` — run focused unit/integration regression checks (`tests/*.test.ts`) with Node's test runner via `tsx`
- `npm run test:render` — after `npm run build`, check real production SSR responses in all three skins (plus the no-cookie default) and JSDOM React interactions (`tests/render/*.test.ts`) without starting a server
- `npm run preview` — preview production build locally
- `npm run gen:retro` — redraw the retro skin's graphics into `public/retro/` (output is committed)
- `npm run gen:og` — redraw the OG card artwork into `src/assets/og/` (output is committed)
- `npm run new-post` — scaffold a new blog post in `src/content/blog/`
- `docker compose up --build` — build and run in container (maps port 8484 → 4321)

Run `npm run check`, `npm test`, `npm run build`, and `npm run test:render` before committing.

## Key Architecture Decisions

- **Three skins, one site:** Mandy mode (`mandy`, the default via `DEFAULT_SKIN`), the modern skin (`modern`), and a Web 1.0 "retro" skin (`retro`). The active skin is a `kk-skin` cookie resolved in `src/middleware.ts` into `Astro.locals.skin` before anything renders. `Layout.astro` dispatches to `MandyLayout.astro`, `ModernLayout.astro`, or `RetroLayout.astro`, and each `.astro` route branches on `getSkin(Astro)` to render a `mandy-components/Mandy*`, `page-components/*`, or `retro-components/Retro*` body. `parseSkin` lists `modern` explicitly so choosing it over the `mandy` default sticks.
- **Astro for routing/SSR, React for everything rendered:** `.astro` pages do server-side data fetching (content collections, `lastfm.ts`, `cv.json`) and render the skin's React body component with the result as props. Purely presentational components (no interactivity) need no `client:*` directive — Astro renders them to static HTML with zero client JS. Interactive ones (`ThemeBar`, `OnekoToggle`, `Tetris`, `RockPaperScissors`, `StarPairs`, `Tunes`, `PostReactions`, `ReadingTools`, `HeartRate`, `HeartRateCard`, `HeartRateFloat`, `TypingHeading`, `MandyNav`, `MandyEffects`, `MandyBackdrop`, `RetroChrome`, `SkinToggle`, the modern shell's `CommandPalette` / `NavigationProgress` / `ConstellationField`, and the guestbook bodies `GuestbookPage` / `RetroGuestbookPage` / `MandyGuestbookPage`) use `client:load`.
- **Game islands:** `Tetris.tsx` (`src/pages/games/tetris.astro`) is a React island over a pure engine: `src/lib/tetris.ts` (`TetrisEngine`) holds the Guideline rules with no DOM — SRS in full 3×3/4×4 boxes with the published y-up kick tables flipped for the y-down board, 7-bag, hold (returns in spawn orientation), ghost, 2 hidden spawn rows with block-out and lock-out, 0.5s lock delay with a 15-move reset cap, DAS/ARR, Guideline gravity, and T-spin / back-to-back / combo / perfect-clear scoring — and `src/lib/tetrisCanvas.ts` draws it. The engine also queues `GameEvent`s (hard drop, lock, clear with the pre-collapse rows, level up, game over) that the island drains each frame with `takeEvents()`: `src/lib/tetrisEffects.ts` turns them into canvas effects (drop trails, lock flashes, row bursts and particles, Tetris/T-spin/perfect-clear/level-up flashes, screen shake applied to the board wrapper, and a bottom-up grey-out that the game-over dialog waits for), and the island turns clears into stacked DOM callouts (`.kk-tetris-callout--*` in `global.css`). Each callout is removed on `animationend` *or* by a `CALLOUT_MAX_MS` timer, whichever comes first, so a stylesheet that kills the animation can never leave stale text over the board. Under reduced motion every kind uses the motionless `kk-tetris-callout-still` fade (keyframes kept outside any media query), and both skin blankets — retro's `animation: none !important` and Mandy's 0.001ms durations — carry an explicit `.kk-tetris-callout` exception so the fade survives; `tests/tetrisCallouts.test.ts` guards both. Effects are cosmetic only — the engine never waits for them — and reduced motion drops shake, particles and trails, keeping short still fades. The island owns the rAF loop (frames clamped to 100ms), window key handling (ignored in inputs, open dialogs, and with Ctrl/⌘/Alt so the palette shortcut still works), the touch pad (`.kk-tetris-pad` in `global.css`, shown on narrow or coarse-pointer screens) and an always-visible controls legend (keyboard keys on keyboard devices, pad icons on touch ones — `KEY_LEGEND`/`TOUCH_LEGEND` must match the key handler and pad buttons), pause on P/Esc, tab hide, or window blur, and the leaderboard. The game waits for Start and only asks for a name at game over. Its markup keeps the `#board`, `#next`, `#hold`, `#leaderboard`, and HUD ids that `retro.css` targets. `RockPaperScissors.tsx` wraps pre-existing imperative logic (`src/lib/rockPaperScissors.ts`'s `initRockPaperScissors()`) inside a single mount `useEffect`, using `document.getElementById` against the JSX-rendered markup. `StarPairs.tsx` (`src/pages/games/star-pairs.astro`) is a cosmic memory game with 3 board sizes whose pure rules live in `src/lib/starPairs.ts`: the board is never randomised during SSR (dealt after Start to avoid hydration mismatches), each start gets a fresh round ID in the clock effect's dependencies (so restarting during active play resets the timer cleanly without restarting on card flips), play pauses when the tab is hidden, arrow keys + Enter/Space and touch are supported, and personal bests persist in `localStorage`.
- **SSR everywhere for page routes & Sitemap `customPages`:** every route that renders `Layout.astro` is server-rendered. Blog and portfolio `[slug]` pages cannot use `prerender = true` because the skin lives in a request cookie a build-time render can't see (content collections are in-memory at runtime, so SSR costs nothing). Because `@astrojs/sitemap` cannot auto-discover SSR dynamic routes, `astro.config.mjs` feeds them back in via `customPages` derived from filenames in `src/content/` (if `slug` is ever overridden in frontmatter, that helper must read frontmatter instead). `src/pages/og/[...route].ts` is the one remaining prerendered route (request-independent).
- **Theme system:** DaisyUI themes configured in `tailwind.config.mjs` with `data-theme` attribute on `<html>`. Five modern themes: `dark` (default), `light`, `forest`, `spider-man`, `batman`. **`src/lib/theme.ts` is the source of truth** for the list, the default, and the cookie; a new theme needs an entry in `THEMES` there, an entry in `tailwind.config.mjs`, a critical-background line in `ModernLayout.astro`'s inline `<style>`, a `ThemeBar.tsx` swatch, and a `CommandPalette.tsx` theme action. Custom `--surface` and `--accent-dark` CSS vars extend DaisyUI for specific utilities. The choice is stored in **both** `localStorage` and the `kk-theme` cookie — always write through `persistTheme()`, never `localStorage.setItem` alone, or the next server render reverts to the default. Legacy theme names migrate automatically. `ThemeBar` observes the displayed `data-theme` attribute on `<html>` rather than reading storage directly. Theme switching animates via a `startViewTransition` circular reveal (CSS hooks under `html[data-theme-switching]` in `global.css`), with a CSS color-fade fallback (`data-theme-fade`) and instant switch under reduced motion.
- **View transitions / no-FOUC:** `ModernLayout.astro` uses Astro's `<ClientRouter />` for SPA-style navigation. Anti-flash relies on four head pieces: **`data-theme` rendered server-side on `<html>`** from the `kk-theme` cookie (via `locals.theme`), critical inline `<style>` with per-theme `html` backgrounds (correct first paint before the stylesheet loads), an inline script that reconciles the rendered theme with `localStorage` (falling back to the live cookie before a stale HTML attribute when `localStorage` is blocked) and re-applies it on `astro:after-swap` (the router resets `<html>` attributes on every swap, and a page prefetched before a theme change carries the stale one), and page animations in `global.css` (`vt-page-out`/`vt-page-in` on the root group). The server-rendered attribute is the load-bearing part: **an inline script is not guaranteed to run before paint.** Cloudflare Rocket Loader rewrites inline `<script type>` to a token MIME type and replays it after load, which flashed the default blue theme — the pre-paint scripts in both shells carry `data-cfasync="false"` to opt out of it, and Rocket Loader should stay **off** for this site (it also defers Astro's island and ClientRouter modules). Header/footer have `transition:name` so they stay static during navigation; `ThemeBar`, `OnekoToggle`, `SkinToggle`, and the `HeartRate` pill use `transition:persist`. The oneko cat is mounted *inside* the persisted `OnekoToggle` island (`oneko.js` appends next to its own script tag) so it survives navigations; islands that attach global listeners or rAF loops must clean up on unmount since navigation no longer reloads the page (Tetris does this via `game.running = false` + `removeEventListener`).
- **Layout props:** `Layout.astro` (and all three shells behind it, typed in `src/layouts/props.ts`) accepts `title`, `description`, `image`, `isWide`, `ogType`, `publishedTime`, and `modifiedTime` props. Title is auto-formatted as `{title} | KoriKosmos` (homepage uses bare site name).
- **Navigation progress bar:** `NavigationProgress.tsx` (`client:load` + `transition:persist` in `ModernLayout.astro`) shows a slim top bar during ClientRouter navigations, driven by `astro:before-preparation` / `astro:page-load`. A 150ms grace period keeps fast navigations from flashing it; it mainly covers pages with slow SSR fetches (Tunes → Last.fm).
- **Tunes page & resilient Last.fm integration:**
  - Server-side (`src/lib/lastfm.ts`, `src/lib/asyncCache.ts`, `/api/lastfm`): successful Last.fm requests are shared across visitors via a bounded cache with in-flight request coalescing (recent tracks expire after 15s, charts after 15m). Upstream requests have a 5s timeout, public query parameters are validated, outages return uncached 503s, `/now` and `/tunes` render with empty music data when Last.fm is unavailable, and URLs containing the API key are never logged.
  - Client-side (`Tunes.tsx`, `src/lib/lastfmClient.ts`, `src/lib/lastfmTrack.ts`): SSR fetches initial data and passes it as props to `Tunes.tsx`. React state retains chart data by period (including SSR results); non-default periods load on demand with abortable requests owned by the active period so slower responses cannot overwrite a newer selection. Artist and album refreshes settle independently so one failure never discards the other chart, and retries request only failed sections. Live polling (every 30s) refreshes the recent list, updates playback even when the track name is unchanged, pauses in hidden tabs, and cleans up timers/listeners on unmount. `trackArtistName` prefers `#text` and falls back to `name` in duplicate filtering, Tunes, and `/now`, and track titles are normalised across language credits. Missing cover art falls back to a local record illustration.
- **Searchable blog/portfolio & reading tools:**
  - `src/lib/contentDiscovery.ts` + `ContentFilters.tsx`: search (`q`), tag/GitHub-source filtering, and sorting live in shareable URL query parameters and work without JavaScript in all three skins. Full Markdown bodies stay on the server instead of shipping a client search index; page components must preserve the order supplied by `contentDiscovery.ts`. On the retro blog (`blog/index.astro` → `RetroBlogIndexPage.tsx`), global freshness metadata (`newestSlug`, `lastUpdated`, `totalCount`) is derived from the full collection before filtering so the `NEW!` badge, modem caption, update date, and entry total always describe the whole blog.
  - `src/lib/reading.ts`, `PostContents.tsx`, `ReadingTools.tsx`: posts render an estimated reading time and a table of contents built from Astro's rendered heading slugs in all three skins. Article bodies remain static; `ReadingTools` progressively adds a reading-progress strip, active-heading tracking, and section-link / code-block copy buttons, cleaning up its observers, scroll listener, and injected buttons on navigation.
- **Live heart rate:** three islands in `page-components/`, each rendering per-skin vocabulary (Tailwind / `rt-heart*` / `md-heart*`; the shared `kk-heartbeat` keyframes and `kk-heart-widget` frame live in `global.css`):
  - `HeartRate.tsx`: the footer pill in all three shells.
  - `HeartRateCard.tsx`: the `/about` box. `about.astro` places it *between* the split page-body halves (`RetroAboutIntro`/`RetroAboutRest`, `MandyAboutIntro`/`MandyAboutRest`), because an island passed into a static React component as children loses its hydration.
  - `HeartRateFloat.tsx`: a ♥ dock button (above the cat toggle) that opens a draggable floating monitor. Open state and position live in `localStorage`, so it survives the full-reload navigations of retro and Mandy. In modern it is also `transition:persist`ed.
  - Shared pieces: `heartRateParts.tsx` holds the ECG canvas (`EcgTrace`, colour from CSS `color`, a static frame under reduced motion) and the widget iframe. `src/lib/heartRateStore.ts` is one client-side poller (5s, paused while the tab is hidden) shared by all islands on a page via `useSyncExternalStore`, plus the floating window's state. Don't give an island its own `fetch`.
  - Data source: `/api/heartrate`, a proxy over Pulsoid's HTTP API. `src/lib/pulsoid.ts` is server-only and holds the token. `src/lib/pulsoidClient.ts` is pure and tested: one 3s cache shared by every visitor, and readings older than 60s count as offline, so the widget hides when the strap is off. **Fallback:** with no token, or once Pulsoid answers 401/402/403 (the BRO plan lapsed), the proxy returns `mode: 'widget'` and the island frames the free Pulsoid widget from `PULSOID_WIDGET_URL` instead. It backs off for 5 minutes, then retries the token so the native readout returns by itself. Widget URLs are allowlisted to `https://pulsoid.net/widget/view/<id>`. With neither env var set, the shells don't mount the island at all.
- **OG / social images:** `src/pages/og/[...route].ts` uses `astro-og-canvas` (prerendered) to generate cards for the site default (`/og/site.png`), every blog post (`/og/blog/<slug>.png`), and every project (`/og/portfolio/<slug>.png`). `Layout.astro` falls back to `/og/site.png` when no `image` prop is passed; blog/portfolio `[slug]` pages pass their generated card. Fonts are vendored in `src/fonts/` so builds don't hit a font CDN; note the 800-weight TTF registers as the separate family `'Noto Sans ExtraBold'`, not as a weight of `'Noto Sans'`. New content collection entries get OG cards automatically.
  - Cards are drawn over a **constellation starfield** committed to `src/assets/og/`, generated by `scripts/gen-og-assets.mjs` (`npm run gen:og`) — same arrangement as the retro assets, so the build never runs the script. Three variants share one PRNG seed (identical geometry) and differ only in accent, keyed off the `pages` key in `getImageOptions`: site = indigo, blog = sky, portfolio = violet. Output is PNG because CanvasKit's `MakeImageFromEncoded` **has no SVG decoder**; the artwork is composed as SVG for legibility and rasterised with `sharp` at script time. The emitted SVG must contain no `<text>` — librsvg would resolve fonts against the system, which is what vendoring the TTFs exists to avoid. The generator is seeded so re-running is a no-op in the working tree.
  - `astro-og-canvas` draws background → border → `bgImage`, so the starfield PNG carries alpha and the gradient shows through it. It also **clamps the text block to a narrow band below the logo** (see its `minTop`/`maxTop`); with no logo the title is pinned at `padding` and the bottom of the card is dead space, which is why the card mounts the site mark. Bottom-aligning the text is not reachable through this library's options.
- **Link-preview metadata:** `src/layouts/SeoHead.astro` emits the description/canonical/icon and all Open Graph + Twitter tags for **all three** shells — edit there, not in a layout, or the skins drift. It is output-only (props in, `<meta>`/`<link>` out); each shell keeps its own `<title>`, critical CSS, and scripts. `theme-color` drives Discord's embed stripe and mobile browser chrome, and is a fixed indigo because the crawler that reads it has no theme cookie. `og:title` deliberately keeps the full `{page} | {site}` string even though `og:site_name` is also set — Discord shows site name separately, but several clients ignore it and a bare title loses context there. `og:image:width`/`height` are declared so clients pick the large-image layout before fetching. Pages pass `ogType`/`publishedTime`/`modifiedTime` through `Layout.astro` for `article` metadata; only `blog/[slug]` does so far.
- **Header nav:** `NAV_ITEMS` in `src/config.ts` mixes plain links (Blog, Tunes, and an external link to amandata.dev, which `isExternal()` flags) and categorised groups (Me / Work / Play); groups render as CSS-only DaisyUI `dropdown-hover` menus in `ModernLayout.astro`, as a grouped sidebar list in `RetroLayout.astro`, and as native `<details>` disclosures in `MandyNav.tsx`, with the brand wordmark linking home and active link/category highlighted server-side from `Astro.url.pathname`.
- **Command palette:** `CommandPalette.tsx` (`client:load` + `transition:persist` in `ModernLayout.astro`) is a hand-rolled ⌘K/Ctrl-K fuzzy launcher (no kbar dependency) over a `<dialog>`. Link items (pages from `NAV_ITEMS`, blog posts, projects) are built server-side in ModernLayout frontmatter; theme actions live in the component. It opens via the shortcut or any `[data-palette-trigger]` element (delegated listener; the visible trigger button lives in `ThemeBar.tsx`, left of the theme swatches) and navigates with `navigate()` from `astro:transitions/client` to keep view transitions.
- **/now, /uses, and /links pages:** Indie-web convention pages, in the header nav under the "Me" dropdown. `/now` fetches the latest scrobble via `getRecentTracks(1)` server-side. All three skins render these, so their **data lives in `src/data/`** — `now.ts` (the `NOW_UPDATED` date), `uses.ts` (the `USES` array), `links.ts` (the `LINKS` array). Edit there, not in a component. The prose in the `/now` sections lives in `NowPage.tsx` / `RetroNowPage.tsx` / `MandyNowPage.tsx` and has to be edited in all three.
- **Constellation background:** `ConstellationField.tsx` (`client:load` + `transition:persist` in `ModernLayout.astro`, so it runs on every page and survives navigations) draws a full-viewport canvas starfield behind the content — stars link into constellations and to the cursor. It samples theme colors from the DOM (body color + a `text-primary` probe, re-sampled via a `data-theme` MutationObserver) and draws one static frame under `prefers-reduced-motion`. It relies on `bg-base-100` living on `<html>` (not `<body>`) so its fixed `-z-10` canvas paints above the page background — don't move that class back. The canvas needs explicit `w-full h-full` (replaced element: `inset-0` alone doesn't stretch it, which misaligns drawing from the cursor at dpr > 1). It stays in `page-components/` (not `components/`) to keep it out of the design-sync surface.
- **Game scores, guestbook, reactions, and hit counter persistence:** Stored as JSON files in `data/` (`data/scores/`, `data/guestbook.json`, `data/reactions.json`, `data/hits.json`), accessed via `src/lib/jsonStore.ts` (`async-mutex` + write-temp-then-rename for atomic writes). **The Dockerfile does not `COPY data/`** — all of them rely on the Docker volume mount and degrade gracefully if `data/` is not writable.
- **Abuse controls on public write endpoints:** `POST /api/guestbook`, `POST /api/reactions/[slug]`, and `POST /api/scores/[game]` are same-origin only (`isSameOrigin()` in `src/lib/sameOrigin.ts` compares `Origin` against canonical `site`, never `Astro.url.origin`, which is the internal proxy host in production), body-capped (`src/lib/readBody.ts`), and rate-limited (`src/lib/rateLimit.ts`). The structural control for the guestbook is that `signGuestbook()` **rejects** when the book is full instead of evicting the oldest entry, so a flood of spam can never destroy a real signature. Submitted guestbook URLs are allowlisted to `http:`/`https:` via `sanitizeUrl()` and rendered with `rel="nofollow ugc noopener"`.
- **Shared code between server and client:** `src/lib/images.ts`, `src/lib/constants.ts`, `src/lib/contentDiscovery.ts`, `src/lib/reading.ts`, `src/lib/lastfmClient.ts`, `src/lib/lastfmTrack.ts`, `src/lib/lastfmTypes.ts`, and `src/lib/starPairs.ts` are importable from both Astro frontmatter (server) and React components (client bundles). `src/lib/lastfm.ts` and `src/lib/pulsoid.ts` are server-only (use env vars).
- **design-sync scope:** Only `src/components/` (the 4 reusable components) is synced to Claude Design — `src/page-components/` is deliberately a separate directory so page-specific markup doesn't get pulled into that surface. `SkinToggle.tsx` lives in `retro-components/` even though all three shells use it so design-sync doesn't bundle `src/lib/skin.ts`. See `.design-sync/NOTES.md` for sync-specific gotchas (the `node_modules/korikosmos-dev` self-symlink, synth-entry mode, etc.).

## The retro skin (Web 1.0 / webcore mode)

The whole point is that this is a *different site*, not a restyle — the layout, the chrome, and the page bodies are all separate. `SkinToggle.tsx` (rendered in all three shells) writes a `kk-skin` cookie and does a **full** `location.reload()`, never a ClientRouter navigation — the skins are different documents, so swapping one shell's markup into another's would break.

- **Skin resolution:** `src/lib/skin.ts` defines the cookie and `getSkin`/`isRetro`/`isMandy`. `src/middleware.ts` resolves it into `Astro.locals.skin` before anything renders (and resolves `locals.theme` and `locals.mandyTheme` the same way, and bumps the hit counter there, since setting cookies from layout frontmatter races the streamed response). `App.Locals` is declared in `src/env.d.ts`.
- **Layout dispatch:** `Layout.astro` is a thin dispatcher that picks `MandyLayout.astro`, `ModernLayout.astro`, or `RetroLayout.astro`. Pages keep importing `Layout.astro` unchanged.
- **Page bodies:** each `.astro` route branches on `getSkin(Astro)` and renders `mandy-components/Mandy*`, `page-components/*`, or `retro-components/Retro*`. Retro components are a parallel set, not a restyle.
- **No `prerender = true` on any route using `Layout.astro`.** A build-time render has no request, so the cookie is invisible and the toggle silently does nothing. `blog/[slug]` and `portfolio/[slug]` were converted to SSR for this reason (content collections are in-memory at runtime, so it's ~free). `src/pages/og/[...route].ts` stays prerendered — it's request-independent.
- **`src/styles/retro.css` is the single shared vocabulary.** Every retro class is `rt-*` and every rule is scoped under `[data-skin="retro"]`, because `Layout.astro` statically imports all shells and Astro therefore bundles `global.css` (Tailwind + DaisyUI) onto retro pages too. Section 1 is a deliberate **un-reset**: Tailwind's Preflight strips list bullets, heading sizes, `hr`/table borders, and inline images — exactly the browser defaults this aesthetic is built from — so they're handed back explicitly, wrapped in `:where()` so `rt-*` classes still win. Add primitives centrally here; page components use the vocabulary and inline styles, never their own CSS.
- **Colour goes through variables, never literals.** Section 2 defines each sub-theme (`y2k` default, `kawaii`, `geocities`, `cyber`), including the *derived* inks: `--rt-on-accent` / `--rt-on-accent-2` for text sitting on an accent, `--rt-link-hover-ink`, `--rt-focus`, `--rt-heading-ink`, and a per-theme `--rt-rainbow` ramp. Those exist because a single hard-coded `#ffffff` or reused `--rt-accent` is legible in two themes and invisible in the other two (white on geocities' yellow is 1.07:1). They are set as `data-retro-theme` on `<html>` from `localStorage` by an inline pre-paint script in `RetroLayout.astro` (which carries `data-cfasync="false"`; unlike the modern and Mandy themes these are not cookie-backed, so that script *is* the whole mechanism), switched by `RetroChrome.tsx`. Each needs a full var block in `retro.css` §2, a critical-background line in `RetroLayout.astro`, and a swatch in `RetroChrome.tsx`. `RETRO_THEMES`/`DEFAULT_RETRO_THEME` in `src/lib/skin.ts` are the source of truth. Changing the default also means moving the bare `[data-skin='retro']` var block in `retro.css` §2 and the bare `html[data-skin="retro"]` critical-background rule.
- **No `<ClientRouter />` in the retro shell.** Full page loads are period-accurate and avoid cross-skin swap bugs. Consequence: the chiptune in `RetroChrome.tsx` stops on navigation (a fresh page can't resume audio without a new user gesture) and islands remount every page.
- **The interactive islands are wrapped, never forked.** `Tetris.tsx`, `RockPaperScissors.tsx`, `StarPairs.tsx`, `Tunes.tsx`, and `PostReactions.tsx` render unchanged inside `RetroIslandShell.astro` and are restyled from outside by `retro.css` §17. Their logic depends on that exact markup (Rock Paper Scissors drives it via `document.getElementById`, Tetris owns a canvas loop, Tunes holds polling state) — a retro rewrite would render fine and silently stop working or drift from the real game. `RetroIslandShell` is `.astro`, not React, because Astro pre-renders content slotted into a framework component to static HTML, which would strip the island's hydration.
- **Generated graphics:** `scripts/gen-retro-assets.mjs` (`npm run gen:retro`) draws all 35 assets in `public/retro/` — tiles, 88×31 buttons, blinkies, dividers, mascot, cursors — as SVG with animation from CSS embedded in each file (external page CSS does not apply inside an `<img>`). Nothing is downloaded or hotlinked. Output is committed, so the build never runs the script.
- **Shared page data:** `src/data/uses.ts`, `src/data/links.ts`, and `src/data/now.ts` hold the `/uses` list, `/links` list, and the `/now` "updated" date, because **all three** skins render them. Edit the data there, never in a component — a copy in one component updates only one skin. The retro components keep their period flavour (fake window captions, `NEW!` badges) in local lookups keyed by section title/label, so an entry added to the shared data still renders, just without flavour.
- **Accessibility is deliberately not period-accurate:** skip link, real `alt` text, `aria-label`s, and a `prefers-reduced-motion` block in `retro.css` §18 that stops every animation (blink, marquee, rainbow, sparkles). Its one exception is the Tetris callout's motionless fade: without any animation the callout would rely solely on its removal timer, so §18 hands it `kk-tetris-callout-still` back. Add an exception there, not a weaker rule elsewhere, if another island ever needs a still fade. The chiptune defaults to off and only starts from a click. Use the CSS marquee (`.rt-marquee__track`), **not** a real `<marquee>` element — the element scrolls from the browser's layout engine, so no CSS rule can stop it and it keeps moving under reduced motion.
- **Generated-asset gotchas:** graphics with text labels need an opaque plate behind the label — they're drawn on `--rt-panel`, which is near-white in kawaii/y2k and near-black in geocities/cyber, so bare dark text vanishes in half the themes. Because an `<img>` is a separate document, the page's `prefers-reduced-motion` rule cannot reach inside it — each generated SVG needs its own `@media (prefers-reduced-motion: reduce)` query. Keep explanatory comments in `gen-retro-assets.mjs`, not in the emitted SVG: an XML comment may not contain a double hyphen, so a CSS custom property name inside one is a parse error. The script writes in place and prunes stale files rather than deleting `public/retro/`, which would make a running `astro dev` 404 every asset until restarted.

## Mandy mode (the default skin)

**The default skin** (`DEFAULT_SKIN` in `src/lib/skin.ts`): a visitor with no `kk-skin` cookie gets Mandy mode, and `parseSkin` lists `modern` explicitly so choosing it still sticks. Modelled on the general structure of [amandata.dev](https://amandata.dev) (Maan's girlfriend's site) and re-made around Maan's fandoms. Same plumbing as the retro skin: `SkinToggle.tsx` (a three-way switcher in every shell) writes the cookie and does a full reload, `Layout.astro` dispatches to `MandyLayout.astro`, and every route branches on `getSkin(Astro)` to render a `src/mandy-components/Mandy*` body.

- **Sub-themes are fandoms:** `gotham` (Batman, default), `basement` (The Binding of Isaac), `kanto` (Pokémon), `inkwell` (comics). `MANDY_THEMES`/`DEFAULT_MANDY_THEME` in `src/lib/skin.ts` are the source of truth. Unlike the retro sub-theme, this one is **cookie-backed** (`kk-mandy-theme` → `locals.mandyTheme` in middleware) and rendered server-side onto `<html>`, so there is no pre-paint script to be deferred. A new sub-theme needs: an entry in `MANDY_THEMES`, a token block in `mandy.css` §1, a DaisyUI theme of the same `mandy-<name>` in `tailwind.config.mjs`, a critical-background line in `MandyLayout.astro`, a `MANDY_THEME_INFO` entry in `MandyNav.tsx`, and a scene in `MandyBackdrop.tsx`.
- **The sleeping mascot's coat follows amandata's cat:** the hero bat in `MandyHomePage.tsx` gives every pixel a role (`f` fur, `w` wing, `d` shade, `l` light, `p` pink, `e` closed eye), each role is a `--md-mascot-*` variable, and every sub-theme sets its own coat in `mandy.css` §1, each in that fandom's colours: the original dark Batman bat in Gotham (deliberately a shadow on the night sky, found by its yellow eyes), a moonlit tan in Basement, Poké Ball red in Kanto, and Golden/Silver Age gold and silver in Inkwell. Apart from Gotham's intentional silhouette, coats clear 3:1 against their `--md-bg`. A new sub-theme needs all six variables, checked against its background. Keep the sprite's rows palindromic. This is the 16-row mascot, not the 20×7 `PixelBat` emblem, which stays a one-colour silhouette.
- **`data-theme="mandy-<name>"` does double duty:** it is the `mandy.css` token selector *and* a DaisyUI theme. That is how the wrapped islands (Tetris, Star Pairs, Tunes, reactions) recolour without being touched. Never put the sub-theme on a bare name like `dark`/`light` — those are live DaisyUI themes for the modern skin.
- **`src/styles/mandy.css` is the single shared vocabulary**, like `retro.css`: every class is `md-*`, every rule (and every keyframe name) is scoped/prefixed under `[data-skin="mandy"]`, because `global.css` ships on Mandy pages too and amandata's original class names (`.btn`, `.hero`, `.footer`, `.stat`, `.progress`) all collide with DaisyUI. Mandy components use these classes and inline styles, never Tailwind utilities or their own CSS.
- **Shell pieces & no-JS support:** `MandyNav.tsx` (dropdowns from `NAV_ITEMS` as native `<details>`, so they open with JS off — this is the default skin, and `tests/render/pages.test.ts` checks it; React only takes over `open` after hydration for one-menu-at-a-time, arrow keys, and Escape; page search over pages/posts/projects with a `/blog?q=` fallback, theme picker, homepage reading-progress bar), `MandyEffects.tsx` (typewriter, staggered reveals, key-term sweeps, count-ups — all opt-in by markup and fail-open: the hidden states only exist once it adds `md-js` to `<html>`), `MandyBackdrop.tsx` (the self-playing pixel scene that replaces amandata's Othello board; one scene per sub-theme drawn in code into a small buffer upscaled without smoothing, static frame under reduced motion). No `<ClientRouter />`, same reasons as retro.
- **One bat emblem:** `src/page-components/PixelBat.tsx` (`BAT_ROWS`, a 20×7 pixel bat with palindromic rows reduced from Maan's braille-art bat) is the Mandy nav mark, the gotham Bat-Signal, the modern Batman theme swatch, and the skin button's Mandy icon. Edit it there. Keep `scale` a whole number so the pixels stay crisp. The backdrop canvas is upscaled 3× (`PIXEL`), so a wider sprite there gets big fast.
- **Islands are wrapped, never forked**, in `MandyIslandShell.astro` (`.astro` for the same slot-hydration reason as `RetroIslandShell`). Pass `level={0}` when the island brings its own `<h1>` so the heading outline never runs h2 → h1, and `first={false}` when it is not the first section on the page. The guestbook has its own `MandyGuestbookPage.tsx` with the same API calls and `rel="nofollow ugc noopener"` links.
- **Content is Maan's, never Mandy's.** The structure is borrowed; the bio, projects, stats, and CV come from this repo (`src/data/*`, `cv.json`, collections). The `/now` prose lives in three components (`NowPage.tsx`, `RetroNowPage.tsx`, `MandyNowPage.tsx`) that must be edited together. Google Fonts (Pixelify Sans, VT323, Silkscreen, Nunito, Bangers) load only in this shell.

## Style Guidelines

- Use DaisyUI semantic classes (`bg-base-100`, `text-base-content`, `bg-primary`, `text-primary-content`, etc.) for theme-aware colors
- Use `bg-base-200` for card/surface backgrounds, `bg-base-100` for page background
- Use `from-primary to-secondary` for gradient accents
- The custom `hover:bg-accent-dark` utility is defined in `global.css` for the accent dark hover state
- Button style: `bg-neutral text-neutral-content rounded` for game controls, `bg-primary text-primary-content` for CTAs

## Common Patterns & Contributing

- Follow the existing coding style (two-space indentation, semicolons in JS/TS).
- Content collections use `getCollection()` and `getEntry()` from `astro:content`; fetch in `.astro` frontmatter and pass to the page's body component as props (not inside the React component). **Not `getEntryBySlug()`** — it is deprecated and *throws* for these collections rather than returning undefined, so a `if (!entry)` miss branch after it never runs and an unknown slug 500s with an empty body. A dynamic route that misses should `return Astro.rewrite('/404')`, which renders the real 404 page in the active skin and returns a 404 status.
- API routes export `APIRoute` type from Astro and return `new Response()`.
- Components in `src/components/` and `src/page-components/` export both a named export and `export default <Name>` — `export *` (used by design-sync's synth-entry bundler) does not forward default exports, so the named export must exist for any component that might be synced.
- `ProjectCard`'s `project` prop is typed `CollectionEntry<"projects">` (from `astro:content`) for real use in the site. That type isn't resolvable outside Astro's build, so `.design-sync/config.json`'s `dtsPropsFor.ProjectCard` hand-writes an equivalent plain shape for the synced artifact — keep both in sync if the `projects` content schema changes.
- Astro `<Content />` (from `entry.render()`) and other Astro-rendered markup can be passed as `children` to a React component from `.astro` templates — Astro pre-renders slotted content to static HTML before handing it to the framework component.
- Use `<dialog>` elements for modals instead of `prompt()`/`alert()` for new code — `RockPaperScissors`'s blocking `prompt()` username flow is legacy, preserved as-is during the React port rather than redesigned.
- Accessibility: all interactive elements need `aria-label` if text-only isn't descriptive; canvas elements get `role="img"` + `aria-label`.
- Whenever making changes, keep `AGENTS.md`, `CLAUDE.md`, and `README.md` in sync, write documentation in first-person voice from Maan's perspective, append qualitative notes to the bottom of `AGENTS.md`, keep commits focused with a short imperative subject line, never apply a "codex" label to PRs, and run `npm run check`, `npm test`, `npm run build`, and `npm run test:render` before committing.
- Model-specific blog drafts live in `drafts/` at the repository root (outside `src/content/blog/` so they are never rendered on the site), while the consolidated Mandy-mode post is published at `src/content/blog/mandy-mode.md` with affectionate, concrete credit to Mandy and amandata.dev, honest admiration and design envy, and the technical context behind building the skin.
